## Что уточнено относительно исходной базы

- Ожидаемый RED нового согласованного теста: сообщить и продолжить реализацию; неожиданное падение: сообщить и дождаться одобрения исправления. Уже написанный тест защищён в обоих случаях, включая fixtures и настройки запуска.
- «Всегда валиден»: сначала проверить полное отдельное состояние, затем применить изменения; ошибка оставляет исходное состояние неизменным. Pydantic сам не обещает атомарный rollback.
- Default остаётся строго внутри `Field`; показана форма присваивания, понятная статическому анализатору, и сохранена оговорка для `Annotated[..., Field(default=...)]`.
- Иммутабельность включает вложенные значения. Невалидирующее копирование и повторная передача готового экземпляра в `model_validate` не объявлены гарантиями проверки.
- CQS запрещает скрытую запись в query; явный результат command разрешён, как уже требуется существующим доменным методам.
- Качество проверяется результатами команд. Недоступные интеграции, warnings, намеренный RED и skips остаются видимыми; запрет править тесты не обходится ради «зелёного» отчёта.

## Как поддерживать

1. Общие изменения сначала вноси в универсальный файл, затем синхронизируй соответствующие разделы адаптаций в согласованной области работ. NGINX сохраняет собственные разделы архитектуры и проверок.
2. В контексте сервиса держи только назначение, реальные пути/механизмы, команды и существенные ограничения. Перед обновлением сверяй код, `pyproject.toml`, `prek.toml`, CI и fixtures.
3. Не превращай целевые стандарты в заявление о соответствии старого кода. Изменение инструкции само по себе не разрешает миграцию моделей, тестов или публичных контрактов.
4. При проверке файла проверь согласованность правил RED/approval, существование указанных путей и размер цепочки AGENTS.md. Подробные обоснования оставляй в исследовании.
5. Ветки и коммиты сервисов публикуются отдельно; родительский Git не отслеживает содержимое субмодуля как обычные файлы. Обновление gitlink выполняй отдельным согласованным изменением после публикации соответствующего коммита сервиса.
